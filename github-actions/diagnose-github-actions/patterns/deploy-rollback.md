# Deploy and rollback

Trace build provenance to the exact immutable artifact, deployment job, environment gate, OIDC identity, target, health signal, and deployment record. Diagnose gate waits, concurrency cancellation, stale artifacts, incorrect environment selection, cloud trust mismatch, and partial rollout separately.

Rollback means redeploying a previously verified immutable artifact through the normal protected workflow—not rebuilding an old commit. Present impact, prerequisite approval, target, artifact digest, verification, and abort criteria. Never dispatch, approve, deploy, or roll back without explicit external authorization.
